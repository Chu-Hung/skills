# Planning Procedures

> Load when running `/task-flow roadmap`, `/task-flow version`, or `/task-flow project`.
> All three commands require workspace mode (WORKSPACE.md + specs repo). In standalone mode, inform the user and exit gracefully.

---

## Roadmap

`specs/roadmap.md` is the strategic document that ties versions to goals. It is **user-owned** — task-flow only scaffolds or appends; it never overwrites existing content.

### Create (file doesn't exist)

1. Scaffold from `assets/roadmap-template.md` — drop the HTML comment at the top (template instruction, not roadmap content)
2. Ask:
   - Product name
   - First version name (e.g. `v1.0`)
   - Target date (e.g. `2025-Q3`, `2025-09-01`, or `TBD`)
   - 3–5 high-level goals for that version (one sentence each)
3. Write the file to `specs/roadmap.md`
4. Stage and commit in the specs repo:
   ```bash
   cd "$SPECS" && git add roadmap.md && git commit -m "docs: init roadmap"
   ```
5. Print: "specs/roadmap.md created. Run `/task-flow version <name>` to create the matching GitHub Milestone."

### Update (file exists)

1. Read and display `specs/roadmap.md`
2. Offer actions:
   - **a) Add new version section** — ask for version name, target date, goals; append to file
   - **b) Mark version as shipped** — add `· shipped {date}` to the version heading
   - **c) Edit goals** — open the file for manual editing (print the path)
3. For options a/b: stage and commit with `docs: update roadmap`

### Display only

Read `specs/roadmap.md` and print it. No write operations.

## Version

`specs/versions.md` is an **auto-generated** registry. Never ask the user to edit it.

### Create a version milestone

```bash
# Inputs from user
V="$1"          # e.g. v1.0
DUE="$2"        # e.g. 2025-09-01 (optional — leave blank if not set)
DESC="$3"       # short description (optional)

# Build milestone payload
DUE_ISO=""
[ -n "$DUE" ] && DUE_ISO="\"due_on\": \"${DUE}T00:00:00Z\","

PAYLOAD=$(cat <<JSON
{
  "title": "$V",
  $DUE_ISO
  "description": "$DESC"
}
JSON
)

# Create on every repo in ALL_REPOS
for REPO in $ALL_REPOS; do
  EXISTING=$(gh api "repos/$ORG/$REPO/milestones" -q ".[] | select(.title==\"$V\") | .number" 2>/dev/null)
  if [ -z "$EXISTING" ]; then
    gh api "repos/$ORG/$REPO/milestones" --method POST --input - <<< "$PAYLOAD" \
      | jq -r '"  ✓ " + .html_url'
  else
    echo "  ⚠  $REPO: milestone $V already exists (#$EXISTING) — skipping"
  fi
done
```

### Update specs/versions.md

After creating milestones, upsert a row into the registry:

```bash
VERSIONS_FILE="$SPECS/versions.md"

# Create file if needed
if [ ! -f "$VERSIONS_FILE" ]; then
  cat > "$VERSIONS_FILE" <<'MD'
# Version Registry
<!-- auto-generated by /task-flow version — do not edit manually -->

| Version | Target | Status | Repos |
|---------|--------|--------|-------|
MD
fi

# Append row (check for duplicate first)
if ! grep -q "| $V |" "$VERSIONS_FILE"; then
  STATUS="planned"
  REPO_LINKS=$(for R in $ALL_REPOS; do echo -n "[$R](https://github.com/$ORG/$R/milestones) "; done)
  printf "| %s | %s | %s | %s |\n" "$V" "${DUE:-TBD}" "$STATUS" "$REPO_LINKS" >> "$VERSIONS_FILE"
fi

cd "$SPECS" && git add versions.md && git commit -m "chore: register milestone $V"
```

### Mark version shipped

```bash
# Usage: /task-flow version <name> --ship
# Updates the status column in specs/versions.md to "shipped"
sed -i '' "s/| $V | \(.*\) | planned /| $V | \1 | shipped /" "$VERSIONS_FILE"
cd "$SPECS" && git add versions.md && git commit -m "chore: mark $V as shipped"
```

## Project

Creates a GitHub Project (v2) at the org level and links all team repos.

### Pre-check

```bash
# gh project requires the 'project' scope — check first
gh auth status --active 2>&1 | grep -q "'project'" || {
  echo "WARNING: Your gh token may not have the 'project' scope."
  echo "Re-authenticate with: gh auth login --scopes project"
}
```

### Create project

```bash
# Inputs from user
PROJ_TITLE="$1"   # e.g. "v1.0 — Storefront Launch"
PROJ_DESC="$2"    # short description

read -r PROJECT_URL PROJECT_NUM < <(gh project create \
  --owner "$ORG" \
  --title "$PROJ_TITLE" \
  --format json | jq -r '"\(.url) \(.number)"')
[ -n "$PROJECT_NUM" ] || { echo "ERROR: project create failed."; exit 1; }

echo "Project created: $PROJECT_URL"
```

### Link repos and add fields

```bash
# PROJECT_NUM comes from `gh project create` above — no title lookup
# Link each repo
for REPO in $ALL_REPOS; do
  gh project link "$PROJECT_NUM" --owner "$ORG" --repo "$ORG/$REPO" 2>/dev/null \
    && echo "  ✓ linked $REPO" \
    || echo "  ⚠  could not link $REPO (may need manual linking)"
done
```

Save it as the default project (ask first if `PROJECT_NUMBER` is already set to something else):

```bash
CUR=$(grep '^PROJECT_NUMBER=' "$_WS/.task-flow" 2>/dev/null | cut -d= -f2)
if [ -z "$CUR" ]; then
  # Hand-edited file may lack a trailing newline — add one so the append isn't glued on
  [ -n "$(tail -c1 "$_WS/.task-flow" 2>/dev/null)" ] && echo >> "$_WS/.task-flow"
  echo "PROJECT_NUMBER=$PROJECT_NUM" >> "$_WS/.task-flow"
elif [ "$CUR" != "$PROJECT_NUM" ]; then
  echo "Default project is #$CUR — replace with #$PROJECT_NUM? (ask user; on yes:)"
  # sed -i '' "s/^PROJECT_NUMBER=.*/PROJECT_NUMBER=$PROJECT_NUM/" "$_WS/.task-flow"
fi
```

### Use what the Project already has — add no fields

| Need | Built-in Project feature |
|---|---|
| Task status | default **Status** field (`Todo` · `In Progress` · `Done`) |
| Version | built-in **Milestone** field |
| Area / type | issue **Labels** field |
| Todo on create | workflow **Item added to project → Todo** |
| Done on close / merge | workflows **Item closed → Done**, **Pull request merged → Done** |
| Reopen | workflow **Item reopened → In Progress** (optional) |
| Auto-add issues | workflow **Auto-add to project** (filter `is:issue`) |

- Workflows are UI-only (no API) — print `$PROJECT_URL/workflows` and ask the user to enable the rows above.
- Need `Blocked`? Add it as a Status option in the UI; `sync` renders it as its own section automatically.

### After creation

1. Print the project URL + workflows URL
2. Remind: "New issues go to this default project via `--project`. For existing issues: `gh project item-add $PROJ_NUM --owner $ORG --url <issue-url>`."
3. Suggest syncing: "Run `/task-flow sync` to regenerate tasks.md from Project Status."

## Roadmap/version pre-check for `add` (workspace mode)

Run this before collecting any issue fields:

```bash
# 1. Check roadmap
ROADMAP="$SPECS/roadmap.md"
if [ ! -f "$ROADMAP" ]; then
  echo "⚠  No roadmap found at specs/roadmap.md."
  echo "   Run \`/task-flow roadmap\` to create one, or type 'skip' to continue without roadmap context."
  read -r SKIP_ROADMAP
  [ "$SKIP_ROADMAP" != "skip" ] && exit 0
else
  echo "── Roadmap versions ──────────────────────────────"
  grep "^## " "$ROADMAP" | sed 's/^## /  /'
  echo ""
fi

# 2. List available milestones from specs repo
echo "── Available milestones ──────────────────────────"
MILESTONES=$(gh api "repos/$ORG/specs/milestones" -q '.[].title' 2>/dev/null)
if [ -z "$MILESTONES" ]; then
  echo "  (none — run \`/task-flow version\` to create one)"
else
  echo "$MILESTONES" | sed 's/^/  /'
fi
echo "  backlog"
echo ""

# 3. Ask user to pick
echo "Which version does this task belong to? (or 'backlog')"
```

Validate the answer: if the user picks a named version that has no GitHub milestone yet, print:
> "Milestone '{version}' doesn't exist on GitHub yet. Run `/task-flow version {version}` to create it across all repos, then retry."

And exit — do not create the issue. This ensures every issue is tied to a real milestone before it's created.
